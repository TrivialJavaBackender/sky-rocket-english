# gen-module — генерация модуля по минимальному контексту

Аргументы: `$ARGUMENTS` — слаг курса, затем номера модулей и/или чек-пойнты
(`de-a2 4 5`, `en-c1 7`, `de-a2 cp-a`). Пусто — спросить, какой курс и какие модули.

Задача: создать `courses/<slug>/content/module-NN/` (7 файлов) или
`courses/<slug>/content/<checkpoint-dir>/` (2 файла). Ничего вне целевых
директорий не трогать.

## Принцип стоимости — читать ТОЛЬКО необходимое

Генерация YAML требует двух вещей: **форму файлов** и **предметную область
модуля**. Всё остальное, что кажется нужным, либо проверяется автоматически
`pnpm sync`, либо не нужно вовсе. Не читать целиком — значит не платить за это
токенами.

**`pnpm sync` — валидатор. Он ловит то, что иначе пришлось бы вычитывать:**

| Проверяется sync'ом (читать источник НЕ нужно) | Как |
|---|---|
| Все формы `content` по 8 типам, поля meta/vocab/theory/reading | zod `lib/content-schema.ts` — кривой YAML отвергается |
| Восстановимость `open_cloze` | `makeOpenClozeContentSchema` по `content-gap-words/<lang>.ts` — знаменательный ответ без `hint` и без полного `answers` роняет синк |

**НЕ проверяется sync'ом — обязано быть в промпте генерации:**

- число заданий по типам (синк требует лишь `core ≥ 1`);
- непересечение лексики между модулями;
- правило опоры (не забегать вперёд);
- лимит метаязыка (глоссарий);
- разброс индексов верных ответов, «одно задание — одна операция», спиральное повторение;
- иммерсия (таблица вместо прозы, стиль определений);
- объём текстов в границах.

### Что читать

| Читать | Зачем | Объём |
|---|---|---|
| `docs/CONTENT-PACKAGE-SCHEMA.md` | канонические формы всех файлов и 8 типов, правило `open_cloze` | весь (≈250 стр.) |
| `courses/<slug>/PLAN.md` — только §1a, карточка модуля из §4, §5, §6, §7 | входной уровень, опись модуля, иммерсия, профиль (числа), роль типов | слайсы, не весь файл |
| один готовый модуль того же курса — **бегло** `theory.yaml` + голова `exercises.yaml` + одна запись `vocab.yaml` | немецкий/целевой идиом, плотность YAML-комментариев, регистр (Sie) | ≈200 стр. |

### Что НЕ читать (и почему)

- ❌ `docs/MODULE-TASK-TEMPLATE.md` — эта команда его замещает.
- ❌ `web/lib/content-schema.ts` — синк и так его применяет; формы есть в схема-доке.
- ❌ `web/lib/content-gap-words/<lang>.ts` — синк проверяет `open_cloze` сам; в промпте достаточно принципа (ниже). Заглянуть только если синк ругнётся на конкретную рамку.
- ❌ `PLAN.md` целиком — только перечисленные слайсы.
- ❌ прочие готовые модули целиком и `diagnostic/` целиком — одного беглого образца хватает; 28 терминов глоссария берутся из §5 PLAN, а не из диагностики.
- ❌ `course.yaml` — трогать не нужно; `meta.yaml` всё равно перезаписывает `title`/`standfirst` при синке.

## Фаза 0 · Подготовка (в основном контексте, один раз на всю пачку)

Механические шаги, дешёвые, дают всё переменное для промптов:

```bash
SLUG=<slug>
# уже занятая лексика — ни одно из этих слов не может стать записью vocab нового модуля:
grep -h "^  - term:" courses/$SLUG/content/*/vocab.yaml | sed 's/^  - term: //' | sort -u
# опись пройденной грамматики — верхняя граница «правила опоры»:
grep -A40 "^grammar_points:" courses/$SLUG/content/module-*/meta.yaml
```

Из PLAN.md вынуть слайсами: §1a (входной уровень), карточку каждого целевого
модуля из §4, §5 (иммерсия + таблица глоссария), §6 (профиль — точные числа),
§7. Это общее для всей пачки, кроме карточки — она на модуль.

**Резервирование доменов при пачке.** Если генерятся сразу несколько модулей,
они пишутся параллельно и не видят лексики друг друга. Поэтому каждому суб-агенту
в «запрещено» идут не только уже закоммиченные термины, но и **якорные слова из
карточек соседей по пачке** (и ближайших ненаписанных модулей) — чтобы одно слово
не попало в два модуля.

## Фаза 1 · Генерация

**Один модуль** — сгенерировать inline (без суб-агента): прочитать схема-док,
бегло образец, выполнить Фазу 0, написать 7 файлов.

**Несколько модулей** — по одному **параллельному** суб-агенту на модуль
(`general-purpose`, opus). Обоснование в конце файла: параллельные мелкие агенты
дешевле и быстрее одного длинного. Основной агент делает Фазу 0 один раз и
вклеивает готовые слайсы + запрещённую лексику в каждый промпт, поэтому суб-агент
читает только схема-док и бегло один образец — больше ничего.

### Шаблон промпта суб-агенту (заполнить `{…}` из Фазы 0)

```
Создай контент-пакет модуля M{N} курса {SLUG} в courses/{SLUG}/content/module-{NN}/
(7 файлов: meta, vocab, theory, text-main, text-extra, exercises, writing).
Ничего вне этой директории не трогай. Целевое ядро (термины, примеры, тексты,
рамки заданий, ответы, модельное письмо) — строго на целевом языке курса, graded
под уровень. Объяснительные леса (explanation, definition, глоссы, note, checklist,
goals) — по режиму §5 PLAN.md: на целевом при погружении, на метаязыке (bridge),
если курс его объявил. Границу по полям взять из §5 дословно.

ЧИТАТЬ только: docs/CONTENT-PACKAGE-SCHEMA.md (формы файлов и 8 типов) и бегло
для стиля courses/{SLUG}/content/{ОБРАЗЕЦ}/theory.yaml + голову exercises.yaml.
Больше НИЧЕГО не читай: карточка, профиль, иммерсия и запрещённая лексика — ниже.

КАРТОЧКА МОДУЛЯ (дословно, meta.yaml.grammar_points повторяет опись без добавлений):
{вставить карточку из PLAN §4}

ПРОФИЛЬ (числа сойтись точно):
{вставить §6 — лексем; лимит теории (spotlights × items); core с разбивкой по
8 типам; review_pool; cloze_cards; watchouts; границы текстов; формат продукции}

ИММЕРСИЯ / МЕТАЯЗЫК (режим — из §5 PLAN.md):
{вставить §5. Общее для обоих режимов: таблица вместо прозы; explanation = 1–2
предложения + пример; definition = перифраза/глосса + синоним/антоним.
— Погружение (target-only): леса на целевом; метаязык только из глоссария (напр.
  28 терминов de-a2), термин конструкции модуля вводится первым пунктом теории,
  сверх списка — показать примером, не называя.
— Метаязык (bridge, напр. de-a1 → English): леса на bridge, ядро на целевом;
  границу по полям взять из §5 дословно; грамм-термины называются прямо на bridge,
  глоссарий и диагностика не нужны.}

ПРАВИЛО ОПОРЫ. Учащийся вправе ПРОИЗВЕСТИ только: входной уровень (§1a) +
описи всех модулей 1..{N}. Пройденная грамматика:
{вставить grammar_points модулей 1..N-1 из Фазы 0}
Конструкции будущих модулей можно давать как ВВОД (в тексте, рамке задания,
дистракторе, модельном ответе), но не как требуемый ответ. Пройди по каждому
ответу в exercises.yaml и cloze_cards и назови источник — опись этого модуля,
конкретного прошлого или входной уровень; не назвал — переделай. Одно задание —
одна операция: ответ не совмещает два неизученных правила.

ЛЕКСИКА. Ровно {лексем} записей: якоря карточки + добор в тех же доменах на
уровне курса (не частотник уровнем ниже). НИ ОДНО из этих слов записью не
становится (в текстах и заданиях употреблять можно):
{вставить занятую лексику + якоря соседей по пачке}
Возвратный/особый глагол, если нужен, даётся словарной единицей с готовыми
формами (как sich treffen в М1), а не требованием построить местоимение.

OPEN_CLOZE — восстановимость. Пропуск на служебном слове (артикль, предлог,
союз, вспомогательный, местоимение) или на голове устойчивой рамки — без
подсказки. Знаменательное слово — обязателен hint со словарной базовой формой.
Класс задан грамматикой, слово нет — весь класс (≥4) в answers. Проверь каждый
пропуск: «может ли сюда встать другое слово, которого нет в answers?». answers
перечисляет ВСЕ валидные варианты, включая синонимы. Синк валит пакет иначе.

РАЗНОЕ. Индексы верных ответов в mc_cloze/grammar_drill/reading_comprehension
распределить по всем позициям, серий из 3+ одинаковых подряд нет, «первый всегда»
недопустим. 2–3 задания на спиральное повторение грамматики прошлых модулей,
пометить YAML-комментарием. word_formation берёт операцию из словообразовательной
описи модуля/прошлых. reading_comprehension несёт passage — цитату из text-main.
Глоссы (3–5) только на словах, чья форма в тексте = словарной. Тексты — настоящий
жанр, не упражнение: ≥⅔ целевых лексем и все целевые конструкции внутри. Watchouts —
по L1-интерференции. В flow-списках YAML строки с «?» брать в кавычки.

ПРОВЕРКА. Пересчитай все числа против профиля. Прогони
`cd web && pnpm sync` — убедись, что [{mNN}] синкается без ошибок и предупреждений;
падает — чини и прогоняй снова. Отчёт: созданные файлы; фактические счётчики;
строка [{mNN}] из sync; что решил не по букве карточки; сомнительные места.
```

### Чек-пойнт (`cp-a`, `cp-b`, `final`, `diagnostic`)

Пакет — только `exercises.yaml` + `writing.yaml` (нет vocab/theory/текстов, значит
`reading_comprehension` исключён — синк записал бы `reading_text_id = null`).
Задания **новые**, не переписанные из модулей. Владелец модуля несётся префиксом
`explanation`: `M0N · <заголовок пункта описи> — …` (у чек-пойнта нет
`grammar_point`). `review_pool: []`. Проверяет только грамматику и лексику своего
блока; правило опоры и лимит метаязыка действуют. Порог и объём письма — из
`course.yaml` (`pass_mark`) и §9 COURSE-DESIGN-GUIDE. Образец конвенций —
`courses/en-c1/content/checkpoint-a/`.

## Фаза 2 · Проверка (основной агент, после возврата суб-агентов)

`pnpm sync` — структурный валидатор. Числа синк не считает, поэтому прогнать
счётчики скриптом (правит путь и печатает всё, что профиль требует сойти точно):

```bash
node - "$SLUG" module-04 module-05 checkpoint-a <<'EOF'
const {readFileSync,existsSync}=require('fs');const {parse}=require('./web/node_modules/yaml/dist/index.js')
const slug=process.argv[2]
for(const d of process.argv.slice(3)){
  const base=`courses/${slug}/content/${d}`, R=f=>parse(readFileSync(`${base}/${f}`,'utf8'))
  const ex=R('exercises.yaml'), cnt=a=>a.reduce((o,x)=>(o[x.type]=(o[x.type]||0)+1,o),{})
  const words=p=>p.body.flat().map(s=>s.t??'').join(' ').split(/\s+/).filter(Boolean).length
  const dist=ty=>{const i=ex.core.filter(x=>x.type===ty).map(x=>x.content.answer);let r=1,m=1;for(let k=1;k<i.length;k++){r=i[k]===i[k-1]?r+1:1;m=Math.max(m,r)}return `[${i}] maxRun=${m}`}
  if(existsSync(`${base}/meta.yaml`)){const v=R('vocab.yaml'),t=R('theory.yaml'),me=R('meta.yaml')
    console.log(`\n${d}: vocab=${v.entries.length} gp=${me.grammar_points.length} spotlights=${t.spotlights.map(s=>s.items.length)} watchouts=${t.watchouts.length} cloze=${t.cloze_cards.length}`)
    console.log('  core',ex.core.length,cnt(ex.core)); console.log('  review',(ex.review_pool||[]).length)
    console.log('  main',words(R('text-main.yaml')),'extra',words(R('text-extra.yaml')))
    for(const ty of ['mc_cloze','grammar_drill','reading_comprehension'])console.log('  '+ty,dist(ty))
  } else { // checkpoint
    const mod={};for(const x of ex.core){const k=(x.explanation.match(/^M0\d/)||['?'])[0];mod[k]=(mod[k]||0)+1}
    console.log(`\n${d}: core=${ex.core.length} review=${(ex.review_pool||[]).length}`,cnt(ex.core),'модули',mod)
  }
}
EOF
```

Дополнительно глазами: правило опоры (запрещённые конструкции в требуемых
ответах — прогнать regex по `answers`/`options[answer]`/`correction`), метаязык вне
глоссария (grep по терминам), совпадение `word_count` в шапке текста с реальным
счётом, `standfirst` в `meta.yaml` ↔ `course.yaml` (при расхождении — привести
`course.yaml` к `meta.yaml`).

## Почему параллельно по модулю, а не одним длинным агентом

Вывод — **параллельные мелкие суб-агенты, по одному на модуль, в пределах блока**.

- Выход фиксирован: ~1200 строк YAML на модуль (~9k токенов) — не экономится.
- Экономится вход. Один агент на N модулей читает общий контекст один раз, но его
  контекст растёт: модуль k пишется, держа в контексте выводы модулей 1..k−1 →
  суммарная нагрузка входа **квадратична** по N.
- N параллельных агентов: каждый остаётся маленьким (ориентировка + свой вывод),
  общий контекст перечитывается N раз, но это дешёвый схема-док, а не выросший
  транскрипт. Линейно по N и быстрее по стенным часам.
- Единственный плюс последовательного — авто-непересечение лексики — снимается
  дёшево: Фаза 0 один раз собирает занятую лексику и якоря соседей и раздаёт как
  «запрещено». Партиция доменов уже в карточках PLAN.

Границей пачки брать **блок** (3–5 модулей): он делит лексическое пространство и
закрывается своим чек-пойнтом. Чек-пойнт генерить **после** контента блока —
отдельным вызовом, ему нужны фактические правила и лексика уже написанных модулей.
