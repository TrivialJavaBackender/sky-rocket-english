# gen-module — генерация модуля по минимальному контексту

Аргументы: `$ARGUMENTS` — слаг курса, затем номера модулей и/или чек-пойнты
(`de-a2 4 5`, `en-c1 7`, `de-a2 cp-a`). Пусто — спросить, какой курс и какие модули.

Задача: создать `courses/<slug>/content/module-NN/` (7 файлов) или
`courses/<slug>/content/<checkpoint-dir>/` (2 файла). Ничего вне целевых
директорий не трогать.

## Принцип стоимости — читать ТОЛЬКО необходимое

Генерация YAML требует двух вещей: **форму файлов** и **предметную область
модуля**. Всё остальное, что кажется нужным, либо проверяется автоматически
`pnpm validate-content`, либо не нужно вовсе. Не читать целиком — значит не
платить за это токенами.

**`pnpm validate-content <slug> <dir…>` — валидатор пакета.** Те же zod-схемы,
что у синка (включая языковое правило восстановимости `open_cloze`), плюс печать
всех чисел профиля — но **без БД**. Это рабочий инструмент суб-агента: `pnpm sync`
он не запускает (см. Фазу 1, «Почему не sync у суб-агента»).

| Проверяется валидатором (читать источник НЕ нужно) | Как |
|---|---|
| Все формы `content` по 8 типам, поля meta/vocab/theory/reading | zod `lib/content-schema.ts` — кривой YAML отвергается |
| Восстановимость `open_cloze` | `makeOpenClozeContentSchema` по `content-gap-words/<lang>.ts` — знаменательный ответ без `hint` и без полного `answers` роняет валидацию |
| Числа профиля | печатает vocab / grammar_points / spotlights / watchouts / cloze_cards / core по типам / review_pool |
| Длина `text-main`/`text-extra` против `content_profile` | считает слова тела с учётом глоссированных сегментов (`g:`), отбрасывая токены без букв (цены, `·`); сравнивает с `[min, max]` из `course.yaml` — вне диапазона роняет прогон (`exit 1`), это гейт, а не печать |
| Разброс верных ответов | печатает ключи, `maxRun` и число занятых позиций по mc_cloze / grammar_drill / reading_comprehension |
| Чек-пойнт | `review_pool` пуст, раскладка заданий по префиксам `M0N` в `explanation` |

**НЕ проверяется машиной — обязано быть в промпте генерации:**

- непересечение лексики между модулями;
- правило опоры (не забегать вперёд);
- лимит метаязыка (глоссарий);
- «одно задание — одна операция», спиральное повторение;
- иммерсия (таблица вместо прозы, стиль определений);
- жанровость текстов и попадание целевой лексики внутрь.

Числа профиля (кроме длины текста) и разброс ключей валидатор **печатает, но не
судит** — сверить их с профилем всё равно надо глазами. Длина `text-main`/
`text-extra` — исключение: против `content_profile` из `course.yaml` валидатор
судит сам (`✗ ВНЕ ПРОФИЛЯ` → `exit 1`).

### Что читать

| Читать | Зачем | Объём |
|---|---|---|
| `docs/CONTENT-PACKAGE-SCHEMA.md` | канонические формы всех файлов и 8 типов, правило `open_cloze` | весь (≈250 стр.) |
| `courses/<slug>/PLAN.md` — только §1a, карточка модуля из §4, §5, §6, §7 | входной уровень, опись модуля, иммерсия, профиль (числа), роль типов | слайсы, не весь файл |
| один готовый модуль того же курса — **бегло** `theory.yaml` + голова `exercises.yaml` + одна запись `vocab.yaml` | немецкий/целевой идиом, плотность YAML-комментариев, регистр (Sie) | ≈200 стр. |

### Что НЕ читать (и почему)

- ❌ `docs/MODULE-TASK-TEMPLATE.md` — эта команда его замещает.
- ❌ `web/lib/content-schema.ts` — валидатор и так его применяет; формы есть в схема-доке.
- ❌ `web/lib/content-gap-words/<lang>.ts` — валидатор проверяет `open_cloze` сам; в промпте достаточно принципа (ниже). Заглянуть только если он ругнётся на конкретную рамку.
- ❌ `PLAN.md` целиком — только перечисленные слайсы.
- ❌ прочие готовые модули целиком и `diagnostic/` целиком — одного беглого образца хватает; 28 терминов глоссария берутся из §5 PLAN, а не из диагностики.
- ❌ `course.yaml` — трогать не нужно; `meta.yaml` всё равно перезаписывает `title`/`standfirst` при синке.

## Фаза 0 · Подготовка (в основном контексте, один раз на всю пачку)

Механические шаги, дешёвые, дают всё переменное для промптов:

```bash
SLUG=<slug>
# уже занятая лексика — ни одно из этих слов не может стать записью vocab нового модуля:
grep -h "^  - term:" courses/$SLUG/content/*/vocab.yaml | sed 's/^  - term: //' | sort -u
# опись пройденной грамматики — верхняя граница «правила опоры»:
grep -A40 "^grammar_points:" courses/$SLUG/content/module-*/meta.yaml
```

Из PLAN.md вынуть слайсами: §1a (входной уровень), карточку каждого целевого
модуля из §4, §5 (иммерсия + таблица глоссария), §6 (профиль — точные числа),
§7. Это общее для всей пачки, кроме карточки — она на модуль.

**Резервирование доменов при пачке.** Если генерятся сразу несколько модулей,
они пишутся параллельно и не видят лексики друг друга. Поэтому в «запрещено»
идут не только уже закоммиченные термины, но и **якорные слова из карточек
всех ненаписанных модулей** (§4 PLAN, не только соседей по пачке) — иначе одно
слово всплывает записью в двух модулях через несколько итераций.

### Общий брифинг — в файл, не в промпты

§1a + §5 + §6 + §7 + запрещённая лексика + описи пройденной грамматики одинаковы
для всей пачки. Вклеивать их в каждый промпт — платить исходящими токенами
(самыми дорогими) за N почти идентичных копий: на пачке из трёх это ~7500 слов
вывода вместо ~1500. Поэтому Фаза 0 записывает всё общее **один раз** в
`<scratchpad>/gen-brief-<slug>.md` и раздаёт суб-агентам путь.

Структура брифинга — ровно те же разделы, что раньше вклеивались:

```markdown
# Брифинг генерации <SLUG> (общее для пачки)
## Целевой/мета- язык и граница по полям   ← §5 PLAN дословно, таблица
## Профиль модуля — числа сойтись точно    ← §6 PLAN дословно
## Роль типов упражнений                    ← §7 PLAN
## Входной уровень                          ← §1a PLAN
## Пройденная грамматика M1..N-1            ← grammar_points из meta.yaml, дословно
## Словообразовательные описи M1..N-1       ← строки «Словообразование» из §4
## НЕ пройдено — в требуемом ответе нельзя  ← явный чёрный список конструкций
## Запрещённая лексика                      ← занятые термины + якоря всех ненаписанных модулей
```

Чёрный список непройденного стоит выписать явно, конструкциями (для de-a1 M6:
дательный, модальные как система, отделяемые, Perfekt, императив, возвратные) —
это то, на чём правило опоры ломается чаще всего, и агенту дешевле прочитать
запрет, чем выводить его из описей.

В промпте суб-агента остаётся только **своё**: карточка модуля из §4, номер,
директория и путь к брифингу.

## Фаза 1 · Генерация

**Один модуль** — сгенерировать inline (без суб-агента): прочитать схема-док,
бегло образец, выполнить Фазу 0, написать 7 файлов.

**Несколько модулей** — по одному **параллельному** суб-агенту на модуль
(`general-purpose`, opus). Обоснование в конце файла: параллельные мелкие агенты
дешевле и быстрее одного длинного. Основной агент делает Фазу 0 один раз, пишет
брифинг в файл и даёт суб-агенту путь к нему, поэтому суб-агент читает только
схема-док, брифинг и бегло один образец — больше ничего.

**Почему не `sync` у суб-агента.** Синк — один процесс на одну БД и на все
курсы: он валидирует чужие директории тоже. Пока сосед по пачке дописывает свой
`theory.yaml`, синк падает у всех, и агенты жгут вызовы на ретраи чужой ошибки.
Поэтому суб-агент валидируется `pnpm validate-content` (только свой пакет, без
БД), а `pnpm sync` основной агент прогоняет **один раз** в Фазе 2.

### Шаблон промпта суб-агенту (заполнить `{…}` из Фазы 0)

```
Создай контент-пакет модуля M{N} курса {SLUG} в courses/{SLUG}/content/module-{NN}/
(7 файлов: meta, vocab, theory, text-main, text-extra, exercises, writing).
Ничего вне этой директории не трогай. Целевой язык курса — {ЯЗЫК}, уровень {УРОВЕНЬ}.
Целевое ядро (термины, примеры, тексты, рамки заданий, ответы, модельное письмо) —
строго на целевом языке, graded под уровень. Объяснительные леса (explanation,
definition, глоссы, note, checklist, goals) — по режиму брифинга (см. ниже).

ЧИТАТЬ ровно три вещи, больше НИЧЕГО:
1. {ПУТЬ К БРИФИНГУ} — общий брифинг курса: граница метаязыка, профиль (числа),
   роль типов, входной уровень, пройденная грамматика, чёрный список непройденного,
   запрещённая лексика. Прочитать ЦЕЛИКОМ и следовать буквально.
2. docs/CONTENT-PACKAGE-SCHEMA.md — формы файлов и 8 типов.
3. Бегло для стиля: courses/{SLUG}/content/{ОБРАЗЕЦ}/theory.yaml + голова
   exercises.yaml + одна запись vocab.yaml.
НЕ читай PLAN.md, course.yaml, content-schema.ts и другие модули — в частности
соседей по пачке: они пишутся параллельно, их файлов может не быть.

КАРТОЧКА МОДУЛЯ (дословно, meta.yaml.grammar_points повторяет опись без добавлений):
{вставить карточку из PLAN §4}

{если модуль сдвигает что-то относительно брифинга — только это: например
`mode: speaking` при устной продукции, или «опись соседа M{N-1} считать
пройденной, его лексику записями не брать».}

ПРАВИЛО ОПОРЫ. Учащийся вправе ПРОИЗВЕСТИ только: входной уровень + описи всех
модулей 1..{N} (всё в брифинге, разделы «Входной уровень», «Пройденная грамматика»,
«НЕ пройдено»). Конструкции будущих модулей можно давать как ВВОД (в тексте, рамке
задания, дистракторе, модельном ответе), но не как требуемый ответ. Пройди по
каждому ответу в exercises.yaml и cloze_cards и назови источник — опись этого
модуля, конкретного прошлого или входной уровень; не назвал — переделай. Одно
задание — одна операция: ответ не совмещает два неизученных правила.

ЛЕКСИКА. Ровно {лексем} записей: якоря карточки + добор в тех же доменах на
уровне курса (не частотник уровнем ниже). Запрещённый список — в брифинге; ни одно
слово оттуда записью не становится (в текстах и заданиях употреблять можно).
Возвратный/особый глагол, если нужен, даётся словарной единицей с готовыми
формами (как sich treffen в М1), а не требованием построить местоимение.

OPEN_CLOZE — восстановимость. Пропуск на служебном слове (артикль, предлог,
союз, вспомогательный, местоимение) или на голове устойчивой рамки — без
подсказки. Знаменательное слово — обязателен hint со словарной базовой формой.
Класс задан грамматикой, слово нет — весь класс (≥4) в answers. Проверь каждый
пропуск: «может ли сюда встать другое слово, которого нет в answers?». answers
перечисляет ВСЕ валидные варианты, включая синонимы. Валидатор валит пакет иначе.

РАЗНОЕ. Индексы верных ответов в mc_cloze/grammar_drill/reading_comprehension
распределить по всем позициям, серий из 3+ одинаковых подряд нет, «первый всегда»
недопустим. 2–3 задания на спиральное повторение грамматики прошлых модулей,
пометить YAML-комментарием. word_formation берёт операцию из словообразовательной
описи модуля/прошлых. reading_comprehension несёт passage — цитату из text-main.
Глоссы (3–5) только на словах, чья форма в тексте = словарной. Тексты — настоящий
жанр, не упражнение: ≥⅔ целевых лексем и все целевые конструкции внутри. Watchouts —
по L1-интерференции. В flow-списках YAML строки с «?» брать в кавычки.

ПРОВЕРКА. Прогони `cd web && pnpm validate-content {SLUG} module-{NN}` — он даёт
и схему, и все числа профиля, и сверку word_count, и разброс ключей. Схема падает
или число разошлось с профилем — чини и прогоняй снова, пока не сойдётся всё.
`pnpm sync` НЕ запускай: он валидирует чужие директории и падает на соседях по
пачке, которые ещё пишутся; синк прогонит основной агент. `pnpm audio` НЕ
запускай ни при каких условиях: он занимает GPU, перезаписывает коммитируемый
`courses/<slug>/audio/manifest.json` (общий на курс — то есть чужой файл) и его
брак надо переслушивать глазами и ушами человека. Озвучку заказывает пользователь
отдельно, после приёмки контента.
Отчёт: созданные файлы; вывод validate-content целиком; что решил не по букве
карточки; сомнительные места.
```

### Чек-пойнт (`cp-a`, `cp-b`, `final`, `diagnostic`)

Пакет — только `exercises.yaml` + `writing.yaml` (нет vocab/theory/текстов, значит
`reading_comprehension` исключён — синк записал бы `reading_text_id = null`).
Задания **новые**, не переписанные из модулей. Владелец модуля несётся префиксом
`explanation`: `M0N · <заголовок пункта описи> — …` (у чек-пойнта нет
`grammar_point`). `review_pool: []`. Проверяет только грамматику и лексику своего
блока; правило опоры и лимит метаязыка действуют. Порог — `pass_mark` из
`course.yaml`; объём письма — из критериев §8 PLAN курса (в §9 COURSE-DESIGN-GUIDE
объёма нет, только порог 75 % и правило «задания новые»). Образец конвенций —
`courses/en-c1/content/checkpoint-a/`.

Разбивка 30 заданий по 7 типам (`reading_comprehension` исключён) — например
6 grammar_drill · 5 mc_cloze · 5 open_cloze · 4 word_formation · 4 error_correction ·
3 collocation_match · 3 key_word_transformation, ровно по 6 на каждый модуль блока.
Чек-пойнт **не зависит** от модулей текущей пачки, если его блок уже написан, —
такой можно запускать сразу, параллельно с ними, а не ждать их возврата.

## Фаза 2 · Проверка (основной агент, после возврата суб-агентов)

Два прогона, оба обязательны:

```bash
cd web
pnpm validate-content <slug> module-06 module-07 checkpoint-a   # схема + все числа профиля
pnpm sync                                                        # заливка в БД, один раз на всю пачку
```

`validate-content` печатает счётчики, сверку `word_count` (с учётом глоссированных
сегментов и без цен/разделителей) и разброс ключей — сверить с профилем построчно.
`sync` после него обязан пройти без ошибок и без предупреждений по целевым
пакетам (`!` про ненаписанные модули и чек-пойнты — норма).

**Правило опоры — regex по требуемым ответам.** Единственная проверка, которую
машина не сделает сама: чёрный список конструкций свой у каждого модуля. Взять его
из брифинга и прогнать по всем полям, где живёт *требуемый* ответ:

```bash
cd /path/to/repo && node - <<'EOF'
const {readFileSync}=require('fs');const {parse}=require('./web/node_modules/yaml/dist/index.js')
const SLUG='de-a1'
// формы из раздела «НЕ пройдено» брифинга — по одному шаблону на пакет
const pat={'module-06':/\b(dem|kann|will|muss|darf|möchte|gemacht|weil|dass|keinen)\b/i,
           'checkpoint-a':/\b(den|einen|keinen|mich|dich|ihn|uns|euch|dem|kann|will|gibt)\b/i}
for(const d of Object.keys(pat)){
  const ex=parse(readFileSync(`courses/${SLUG}/content/${d}/exercises.yaml`,'utf8'))
  const hits=[]
  const scan=(list,tag)=>(list||[]).forEach((x,i)=>{const c=x.content
    const req=[].concat(c.answers??[],c.correction??[],c.answer_shown??[],c.words??[],
      Array.isArray(c.options)&&typeof c.answer==='number'?[c.options[c.answer]]:[]).filter(Boolean).join(' | ')
    if(pat[d].test(req))hits.push(`${tag}#${i} ${x.type}: ${req}`)})
  scan(ex.core,'core'); scan(ex.review_pool,'review')
  try{const th=parse(readFileSync(`courses/${SLUG}/content/${d}/theory.yaml`,'utf8'))
    th.cloze_cards.forEach((c,i)=>{if(pat[d].test(c.text))hits.push(`cloze#${i}: ${c.text}`)})}catch{}
  console.log(`\n=== ${d} === ${hits.length?hits.join('\n'):'чисто'}`)
}
EOF
```

Хит — ещё не нарушение: запрещённая форма в *рамке* задания (`pre`/`post`) законна,
она ввод. Смотреть, стоит ли она в ответе. По `cloze_cards` regex бьёт по всему
тексту карточки — там проверять, что запрет вне `{{c1::…}}`.

Ещё глазами: метаязык вне глоссария (grep по терминам при погружении), кириллица
в пакетах (`grep -rn "[А-Яа-я]"` — в целевых полях её быть не должно),
непересечение лексики по голове существительного, `standfirst` в `meta.yaml` ↔
`course.yaml` (при расхождении — привести `course.yaml` к `meta.yaml`; `meta.yaml`
всё равно побеждает при синке).

## Отчёт

Созданные файлы; таблица фактических счётчиков против профиля; строки sync; что
решено не по букве карточки; сомнительные места. Аудио (`language: de`) команда не
трогает — после приёмки нужен отдельный `pnpm audio -- --course <slug> --module module-NN` + `pnpm sync`.

Брифинг из Фазы 0 — черновик в scratchpad, в репозиторий его не коммитить: он
производный от `PLAN.md` и устареет.

## Почему параллельно по модулю, а не одним длинным агентом

Вывод — **параллельные мелкие суб-агенты, по одному на модуль, в пределах блока**.

- Выход фиксирован: ~1200 строк YAML на модуль (~9k токенов) — не экономится.
- Экономится вход. Один агент на N модулей читает общий контекст один раз, но его
  контекст растёт: модуль k пишется, держа в контексте выводы модулей 1..k−1 →
  суммарная нагрузка входа **квадратична** по N.
- N параллельных агентов: каждый остаётся маленьким (ориентировка + свой вывод),
  общий контекст перечитывается N раз, но это дешёвый схема-док, а не выросший
  транскрипт. Линейно по N и быстрее по стенным часам.
- Единственный плюс последовательного — авто-непересечение лексики — снимается
  дёшево: Фаза 0 один раз собирает занятую лексику и якоря ненаписанных модулей
  в брифинг. Партиция доменов уже в карточках PLAN.

**Замеры на пачке de-a1 (M6 + M7 + cp-a, три параллельных агента):** ~355k
токенов суб-агентов и 116 вызовов инструментов вернулись тремя отчётами по
~400 слов, стенных часов ~14 минут. Inline это дало бы те же ~3600 строк YAML
плюс всю отладку в основном контексте. Два места, где было заплачено зря и что
теперь исправлено: вклейка общего контекста в каждый промпт (~7500 слов вывода
вместо ~1500 → брифинг в файл) и три параллельных `pnpm sync`, где два агента
ретраились на недописанном соседе (→ `pnpm validate-content` у суб-агента,
`sync` один раз у основного).

Границей пачки брать **блок** (3–5 модулей): он делит лексическое пространство и
закрывается своим чек-пойнтом. Чек-пойнт генерить **после** контента блока —
отдельным вызовом, ему нужны фактические правила и лексика уже написанных модулей.
