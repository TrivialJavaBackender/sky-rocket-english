# gen-course — план курса по языку и уровню

Аргументы: `$ARGUMENTS` — язык (ISO 639-1 или имя), **целевой** уровень (`A1`, `B1`; либо
переход `A1→A2` — берётся цель), опционально `bridge` (метаязык). Пусто — спросить, какой
язык и уровень.

Задача: создать **план курса** — `courses/<slug>/PLAN.md` + `courses/<slug>/course.yaml`,
строку в `COURSE_ROOTS` (`web/content.config.ts`), при необходимости
`web/lib/content-gap-words/<lang>.ts`, и прогнать `pnpm sync` как валидатор скелета.
**Это план, а не контент** — модули потом генерирует `/gen-module <slug> <N…>`. Ничего в
`courses/<slug>/content/**` не создавать.

Слаг курса: `<lang>-<target-lowercase>` (`de-a1`, `en-c1`, `de-a2` для перехода A1→A2).

## Метаязык — решение по уровню (главное обобщение команды)

На низких уровнях полное погружение нечитаемо: читать метаязыковое объяснение на целевом
языке ещё нечем. Поэтому у курса есть **метаязык (bridge)** — язык строительных лесов.
Правило по умолчанию, выводимое из целевого уровня:

| Целевой уровень | bridge по умолчанию | Что на bridge |
|---|---|---|
| A1, A2 | **English** | scaffolding: `explanation`, `definition`, глоссы, `checklist`, `goals`, заголовки шагов/блоков, `standfirst` |
| B1, B2, C1, C2 | **none** (полное погружение) | ничего — весь контент на целевом языке |

Третий аргумент переопределяет: `de A1 ru` → русский bridge; `de A1 none` → форсировать
погружение; `en C1 en` бессмысленно (bridge = целевой) — отвергнуть.

Граница target/scaffolding (какое поле пакета на каком языке) документируется в **§5
генерируемого PLAN.md**; готовый образец границы — `courses/de-a1/PLAN.md` §5. Родовое
правило и обоснование — `docs/COURSE-DESIGN-GUIDE.md` §10. `/gen-module` читает эту границу
из §5 и применяет её при генерации контента.

**Метаязык нигде не хранится в БД и не влияет на движок** (`course.yaml`-схема не `.strict()`
— поле было бы срезано; единственная языко-зависимая проверка — `open_cloze` по
`content-gap-words/<lang>.ts`, а она смотрит на немецкий/целевой ответ). Он живёт в PLAN.md
как авторская конвенция — поэтому отдельная миграция или правка приложения не нужны.

## Принцип стоимости — читать ТОЛЬКО необходимое

Как в `/gen-module`: `pnpm sync` — валидатор. Он ловит кривой `course.yaml` (zod
`web/lib/course-schema.ts`: суммы минут сессий, ссылки чек-пойнтов на блоки, уникальность
слагов). Читать вручную это не нужно.

| Читать | Зачем |
|---|---|
| `docs/COURSE-DESIGN-GUIDE.md` целиком | весь метод: рамка §2, расчёт объёма §3, дозирование теории §4, инвентарь грамматики §5, темы/лексика §6, протокол §7, каталог упражнений §8, чек-пойнты §9, метаязык §10, DoD §11, профиль §12 |
| **один образец того же режима**: `courses/de-a1/` (если bridge≠none) или `courses/en-c1/` (если погружение) — `PLAN.md` бегло + `course.yaml` целиком | форма PLAN.md и скелета, стиль профиля, английские/целевые заголовки шагов |

**Не читать:** `web/lib/*.ts` (sync их и так применяет); готовые `content/`-модули (это план,
а не контент); `docs/MODULE-TASK-TEMPLATE.md` (нужен `/gen-module`, не здесь).

## Фаза 0 · Research (read-only web)

По (язык, целевой уровень) установить и кратко зафиксировать источники — они идут в §1/§2
PLAN.md как обоснование, а не авторское усмотрение:

- **Экзаменационный ориентир** — самый признанный экзамен уровня и **формат его частей**
  (он задаёт типы заданий и формат Abschlusstest): например Goethe/telc/ÖSD для `de`,
  Cambridge (KET/PET/FCE/CAE/CPE) для `en`, DELE/SIELE для `es`, DELF/DALF для `fr`,
  TORFL/ТРКИ для `ru`, JLPT для `ja`.
- **Дельта CEFR** — can-do дескрипторы: чем вход уровня отличается от его цели (для §1
  таблицы «что отделяет нижний уровень от верхнего»).
- **Инвентарь уровня** — размер официального словника (если есть Wortliste/wordlist) и
  грамматические темы, которые вводит уровень.

Инструмент — `WebSearch` / `WebFetch`.

## Фаза 1 · Числа (интерполяция по COURSE-DESIGN-GUIDE §3)

Опорные строки — `de-a2` (54 ч / 14 мод / 30 лексем / core 52) и `en-c1` (80 ч / 15 мод /
45 лексем / core 66). Новый курс интерполируется между ними:

- **бюджет часов** — реалистичный, нижняя граница институциональных (обоснование как в §1
  de-a2: нет групповых накладных, ошибка возвращается сама, карточки вне бюджета).
- **часы на модуль** = сумма минут протокола; ниже уровень → короче сессии (A: 4×~50–55′;
  B2+: 4×~60–75′).
- **число модулей** = (бюджет − служебные 10–15 %) / часы на модуль.
- **лексем/модуль** — 24–30 на A-уровнях, 45 на B2+ (потолок; выше колода не закрывается за
  15 мин).
- **разбивка core** по восьми типам — столько, сколько влезает в минуты шагов `exercise_set`,
  не круглым числом.
- **лимит теории** по §4: A1–A2 ≤2×4 (8), B1–B2 ≤3×5 (15), C1+ ≤5×6 (30).

## Фаза 2 · Запись

1. **`PLAN.md`** (по-русски, автор-facing) — все разделы по образцу `de-a1`/`de-a2`:
   метод + таблица дельты · **§1a входной уровень** (замкнутый список, только лингв.
   категории, готовые фразы отдельным классом, привязка к экзамену — guide §8) · архитектура
   часов (сходится до сотых) · протокол 4 сессий · **§4 роадмап** (одна крупная тема на
   модуль, forward-only, спиральное повторение — guide §5) · **§5 метаязык** (граница
   target/scaffolding, если bridge≠none) · §6 профиль модуля (guide §12) · §7 типы упражнений
   · §8 критерии уровня.
2. **`course.yaml`** — скелет: `slug`, `language`, `level_label`, `position` (следующий
   свободный или вставить по педагогическому порядку, сдвинув соседей). Блоки (3–5 модулей),
   чек-пойнты, протокол. **Diagnostic** — только если у входа есть что картировать (переход
   между уровнями); для курса «с нуля» опустить (см. de-a1). Заголовки шагов — на bridge,
   если bridge≠none, иначе на целевом (как de-a2). Суммы минут сессий = `planned_minutes`
   (иначе sync валит с именем сессии).
3. **`COURSE_ROOTS`** (`web/content.config.ts`) — добавить `'courses/<slug>'`.
4. **`content-gap-words/<lang>.ts`** — если файла для языка ещё нет, создать по образцу
   `de.ts`/`en.ts` (закрытый класс языка: артикли и детерминативы во всех формах, местоимения,
   предлоги, союзы и подчинительные, вспомогательные и модальные в частотных формах,
   отрицание, вопросительные слова, частицы; плюс головы устойчивых рамок) и зарегистрировать
   в `content-gap-words/index.ts`. Без файла sync не пройдёт (внятная ошибка). Если язык уже
   есть (`de`, `en`) — не трогать.

## Фаза 3 · Валидация

- `cd web && pnpm sync` — курс появляется целиком, без ошибок и предупреждений (директории
  модулей пустые → warning + skip по дизайну `content.config.ts`).
- **DoD курса** (`docs/COURSE-DESIGN-GUIDE.md` §11): часы = модули + чек-пойнты, сверены с
  бюджетом до сотых; сумма минут каждой сессии = её `planned_minutes`; лимит теории §4
  соблюдён; грамматика forward-only, в каждом модуле спиральное повторение; §1a — замкнутый
  список; для языка есть `content-gap-words/<lang>.ts`.
