# Шаблон ТЗ субагенту — генерация модуля

Родовой шаблон, одинаковый для всех курсов. Всё курсоспецифичное подставляется из двух мест:

- **карточка модуля** — `courses/{COURSE_SLUG}/PLAN.md`, раздел «Роадмап», М{N};
- **профиль модуля** — `courses/{COURSE_SLUG}/PLAN.md`, раздел «Профиль модуля» (объёмы, язык, разбивка по типам).

Схема пакета — `docs/CONTENT-PACKAGE-SCHEMA.md`. Как выводятся числа профиля — `docs/COURSE-DESIGN-GUIDE.md`.

## Промпт

```text
Разработай модуль M{N} курса {COURSE_SLUG}.

ИСТОЧНИКИ
- карточка модуля M{N} (тема, грамм-подтемы, домены лексики с якорями,
  названия текстов, жанр продукции): courses/{COURSE_SLUG}/PLAN.md
- профиль модуля (объёмы, язык, разбивка core по типам): там же
- схема пакета и формы content: docs/CONTENT-PACKAGE-SCHEMA.md

ЯЗЫК: весь контент — строго целевой язык курса, graded под уровень из профиля.
Ни одного слова на языке-посреднике ни в одном файле — включая пояснения к
ответам и чек-листы. На уровнях A1–A2 действуют правила иммерсии из
COURSE-DESIGN-GUIDE.md §10: таблица вместо прозы, метаязык только из
Grammatik-глоссария диагностики, объяснение — 1–2 предложения плюс пример.

Сгенерируй пакет courses/{COURSE_SLUG}/content/module-{NN}/:

1. meta.yaml — slug, title, standfirst, grammar_points (дословно опись из
   карточки модуля, без добавлений), тексты, production;
   goals (3–4 can-do), каждая — объект {text, achieved_by}: грамматические цели
   → workout, лексическая → input, продукционная → output.

2. vocab.yaml — ПОЛНЫЙ объём записей из профиля (якоря из карточки модуля +
   добор в тех же доменах, уровень курса, не частотник уровнем ниже):
   term, tag, definition, use_cases (2–3 в разных контекстах), collocations,
   register.

3. theory.yaml — grammar spotlights (title, intro, items: form / example / note)
   + watchouts (частотные ошибки, отбор — L1-интерференция) + cloze_cards
   (text с {{c1::…}}, hint — базовая форма ответа, rule).
   ЛИМИТ ТЕОРИИ ИЗ ПРОФИЛЯ — жёсткий. Не помещается — значит, тема шире
   модуля; сообщи об этом, а не ужимай формулировки.

4. text-main.yaml — основной текст под заявленным названием и объёмом:
   ≥⅔ целевых лексем и все целевые конструкции, аутентичный жанр, не
   упражнение; body — сегменты {t: "…"} | {g: gloss_key}; glosses 3–5.

5. text-extra.yaml — второй текст заявленного жанра и объёма.

6. exercises.yaml — core ровно по разбивке из профиля + review_pool.
   У каждого задания: ровно один верный ответ, answer + explanation на целевом
   языке. group_key: grammar | reading | vocab. 2–3 задания — на грамматику
   прошлых модулей (спиральное повторение).

   ПРАВИЛО ОПОРЫ. Задание опирается ТОЛЬКО на: (1) описи этого модуля —
   грамматическую, словообразовательную и лексическую, (2) описи прошлых
   модулей, (3) входной уровень из PLAN.md. Забегать вперёд нельзя.
   word_formation берёт операцию из СЛОВООБРАЗОВАТЕЛЬНОЙ описи, а не из
   грамматической темы модуля. Проверять по тому, что учащийся должен
   ПРОИЗВЕСТИ, а не по тому, что стоит в условии: конструкцию из будущего
   модуля можно дать в рамке задания, в тексте, в дистракторе и в модельном
   ответе как ввод, но не как требуемый ответ. Одно задание — одна
   проверяемая операция: если ответ требует и словоформы, и падежа, а падеж
   ещё не проходили, это два разных умения в одном пропуске.

   Индексы верных ответов РАСПРЕДЕЛЯТЬ равномерно: в mc_cloze / grammar_drill /
   reading_comprehension встречаются все позиции опций, серий из 3+ одинаковых
   подряд нет, «правильный всегда первый» недопустим.

   ПРОПУСК ОБЯЗАН БЫТЬ ВОССТАНОВИМ (open_cloze). Пропуск на служебном слове или
   на голове устойчивой рамки — подсказка не нужна. Знаменательное слово,
   выбранное лексически, — `hint` ОБЯЗАТЕЛЕН и содержит словарную базовую форму
   (`hint: know` для knowing), а не название части речи. Грамматика задаёт класс,
   но не слово — перечислить в `answers` весь класс (≥4).
   `answers` в любом типе со свободным вводом содержит ВСЕ валидные варианты:
   пропущенный синоним — ложная ошибка в грейдинге.
   Правило проверяется sync'ом, списки служебных слов — content-gap-words/<lang>.

7. writing.yaml — задание жанра из профиля (mode: writing | speaking), prompt,
   model answer заявленного объёма, checklist самопроверки.

Флеш-карточки отдельно не пишутся: sync деривирует из vocab.yaml две карточки
на запись (узнавание term→definition и воспроизведение definition→term).
Колода — только лексика. cloze_cards из theory.yaml становятся упражнениями
open_cloze в review-пуле, поэтому hint пиши как подсказку-основу для ответа,
а rule — как разбор.

Definition of Done — чек-лист ниже; каждый пункт проверить перед сдачей.
```

## Definition of Done — родовой

- [ ] Ни одного слова на языке-посреднике; определения и объяснения — graded под уровень курса.
- [ ] YAML валиден и соответствует `docs/CONTENT-PACKAGE-SCHEMA.md`; `pnpm sync` проходит.
- [ ] У каждого задания ровно один верный ответ и объяснение на целевом языке; формы `content` соответствуют типам плеера.
- [ ] Индексы верных ответов перемешаны: в каждом choice-типе встречаются все позиции опций, серий из 3+ одинаковых `answer` подряд нет.
- [ ] Каждый `open_cloze` восстановим: служебное слово / устойчивая рамка — без подсказки; знаменательное слово — с `hint` в базовой форме; класс без конкретного слова — с полным набором `answers` (≥4). Прогнать глазами: «может ли сюда встать другое слово, которого нет в `answers`?»
- [ ] `answers` во всех типах со свободным вводом перечисляют все валидные варианты, включая очевидные синонимы.
- [ ] Основной текст содержит целевые конструкции и заявленную долю лексем; читается как настоящий текст жанра, а не как упражнение; глоссы расставлены.
- [ ] Задания на спиральное повторение присутствуют (2–3 на грамматику прошлых модулей).
- [ ] **Правило опоры соблюдено:** пройти по списку ответов и для каждого назвать источник — опись этого модуля, опись конкретного прошлого модуля или входной уровень. Ответ, для которого источник не называется, переделывается.
- [ ] `grammar_points` в `meta.yaml` совпадают с грамматической описью карточки модуля; число пунктов теории не больше объявленного в карточке.
- [ ] Каждый `word_formation` проверяет операцию из словообразовательной описи модуля или прошлых модулей.
- [ ] Каждое задание проверяет одну операцию; ответ не совмещает два неизученных правила.
- [ ] Объяснения не формулируют правил из будущих модулей: высокочастотное исключение даётся как словарный факт, обобщение — в своём модуле.
- [ ] Если курс держит глоссарий метаязыка (A-уровни): каждый грамматический термин в теории, `register` и объяснениях есть в глоссарии диагностики. Недостающий термин добавляется в глоссарий до сдачи модуля либо заменяется показом примера.
- [ ] Каждая цель в `meta.yaml` имеет `achieved_by`, и закрывающая её сессия действительно её закрывает.

## Definition of Done — по профилю курса

- [ ] Объём `vocab.yaml` равен заявленному в профиле; у каждой записи есть definition, use cases, collocations, register.
- [ ] Счёт `core` по типам сходится с разбивкой профиля; `review_pool` заявленного объёма.
- [ ] **Лимит теории соблюдён:** число `spotlights` и `items` в каждом — в границах профиля.
- [ ] Объём текстов и модельного ответа — в границах профиля.
- [ ] Жанр продукции и `mode` соответствуют карточке модуля.

## Порядок разработки курса

1. **Пилот:** диагностика + М1 → пройти М1 самому от начала до конца → зафиксировать проблемы (сложность, объём, формат) → откалибровать профиль модуля в `PLAN.md`.
2. **Пачки по блоку:** после калибровки модули генерируются пачками по 3–4 (блок за раз), параллельными субагентами — каждому карточка модуля из плана.
3. **Чек-пойнты:** тесты генерируются после завершения контента блока — отдельная задача со списком фактических правил и лексики блока.
