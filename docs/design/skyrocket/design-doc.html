Design doc

Information architecture, design tokens (light + dark), interaction spec per exercise type, and empty/edge states. The living mockup is Skyrocket.dc.html.

1 · Information architecture

Four persistent destinations answer four questions; everything else is a flow launched from them and closed with ✕ back to its launcher.

Today — “what do I do right now” · one primary CTA → current session
Course — Course map → Module unit → Exercise player · Writing/speaking flow
Review — the three lanes → Flashcard player · Review Slot · Module quiz
Progress — stats, block bars, item-state ladder, schedule
Header (mobile) / rail footer (desktop): course switcher (multi-course from day one) + Settings.

Navigation model

  • Tabs: bottom bar < 980 px, left rail ≥ 980 px. Module unit keeps the Course tab active.
  • Players are modal flows: exercise + flashcard players hide tabs — one exit (✕), no mid-session wandering. State is kept per flow, so an accidental exit resumes.
  • Everything due funnels to Review; Today only summarises it (counts are taps into the hub).
  • Telegram Mini App: the bot deep-links to /review (daily) and /today (session reminders); the same routes serve the PWA.

3 · Interaction spec — exercise player

Shared frame: type kicker + “n of N” · progress squares (ink = current, green = right, red = wrong) · harvested counter. After any check an explanation always renders (English, 1–3 sentences). Wrong answers surface the one-tap harvest button; tapping it confirms in place — “✓ In your deck — first review tomorrow, then 2 d · 7 d · 21 d” — and increments the counter. Enter = Check on all typed items. All missed items auto-join the re-queue regardless of harvesting.

Module page glosses share the harvest affordance: tap a dotted term → gloss card (word, POS, definition, example) with “＋ Add to deck”. Flashcards grade Again/Hard/Good/Easy with visible intervals; “use cases on the back” is mandatory for all three note types.
